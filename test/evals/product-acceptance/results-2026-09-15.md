# Acceptance guidance evaluation — September 15, 2026

## Method

Three independent agents received the same synthetic cases and two unmodified images. They were not given the scoring rubric, audit conclusions, other evaluator answers, or intended verdicts. Each opened both available images. Raw outputs were retained before the primary agent compared their substantive reasoning with the rubric.

The baseline used role/planning instructions from Critical Boiler main `7ec38474320d2c13b6b137f8d563c6dde9f49e8c`. The initial draft replay used the first revised role/planning instructions and routed references. After source review found and corrected two integration issues, a fresh final evaluator read the complete generated instruction set, including AGENTS and the aligned task/orchestrator rules. The [source hashes](evaluated-source-hashes.json) identify the final evaluated templates, generator files, generation test, and fixture inputs; they are not a hash of the entire repository.

All evaluators inherited the same session model/settings. The generated role configurations' model selections were not used as runtime overrides. These were read-only evidence/scope decisions under explicitly supplied fixture authority, not historical-model replays or real BCO workflows. No native tasks, services, or tests were started by evaluators.

## Source review and deterministic validation

Release preparation advances package, generator, and managed contract metadata to 2.6.4 and updates the generation test's expected version. The retained hashes identify the raw pre-release evaluation input, not a post-checkout byte manifest. Only `src/catalog.js` and `test/bco-enhancement.test.mjs` have release-related text changes within that evaluated set, in version literals. Git checkout can also normalize line endings in evaluated text files; the evaluated instructions and fixture content are unchanged. Release validation reruns generation/sync tests against 2.6.4; it does not relabel the prior behavioral replay as a new run.

Independent source review initially found universal assertion requirements remaining in mandatory workflow guidance and guide links that broke under configured output paths. Both were corrected. Final review is clean. Generated links now resolve from configured consumer paths to the configured guide, with spaces, parentheses, and fragments safely encoded. The default and relocated fresh-generation/sync cases pass.

Final `pnpm test` passed all 12 tests; `pnpm check` passed. The two changed generated skills passed `quick_validate.py`. The source CLI's BCO sync dry-run passed against the disposable generated project. Existing context budgets were preserved: an initial 11-word routing overrun was fixed by shortening routing text, not increasing thresholds. No dependency or BCO schema change was made to the package.

## Limits and implication

The baseline also passed. This small, single-pass exercise therefore validates coherent decisions and guards against obvious regressions; it does **not** show that new wording increases success rates. The final replay additionally used generated AGENTS, so it is a compatibility check, not an identical-context causal comparison. Fixture receipts deliberately supply identity and settled-authority facts; evidence collection, long-running autonomy, real model/tool failures, and full project delivery are not evaluated.

The reusable guidance now makes the intended standard explicit and consistent, but it cannot guarantee the next project outcome. The remaining roadmap still needs BCO release-scope/completion semantics, inspectable evidence, and a representative project run under its actual configured models and runtime.
